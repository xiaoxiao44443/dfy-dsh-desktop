# DSH 0.2.0-rc.1 适配

桌面端版本、开发依赖与打包时的内置 DSH 版本同步至 `0.2.0-rc.1`。Electron `43.4.0`、pnpm `11.19.0` 保持不变。

## 接入调整

- 升级官方 npm 包并更新锁文件，继续使用官方 `runCli()` 启动入口；桌面启动器执行 `dsh --version` 返回 `0.2.0-rc.1` 并正常退出。
- 为承载 Harness 的 iframe 增加 `microphone 'src'` 权限策略，只委派给 iframe 的源站。原来此页面的麦克风策略为禁止，语音输入会在浏览器层被拦截。
- 为 macOS 安装包补充 `NSMicrophoneUsageDescription`，并提供简体、繁体中文用途说明。沿用现有签名和运行时加固配置；macOS 系统授权仍需实机验证。
- 桌面桥接、插件启停、版本拒绝诊断、审批通知和主题同步沿用现有接口；兼容检查未发现需要修改 DFY 插件的接口变化。

## 自动化任务

本版将定时任务功能整理为可选的官方组合包 `@deepseek-ai/dsh-experimental-schedule-bundle`。在 **插件 → 官方 → 自动化任务** 打开开关后，侧栏会显示自动化任务入口，不需要重启。未启用时不主动修改用户的选择。

“新建自动化任务”调用 `uiWorkspace.startSession()` 打开新会话，没有独立创建表单；任务由模型在对话中调用 `schedule_create` 建立，并关联到该会话。已有会话也可以创建任务，创建后可在管理页面编辑规则、查看记录或删除。

实测开关可以加载功能、打开任务列表，并在重启后保留启用状态。本次没有创建真实提醒或调用付费模型。任务投递仍依赖 Harness 进程运行，托盘驻留和彻底退出的行为延续已有实现。

## 验证

- 类型检查、构建通过；63 个测试文件共 717 项通过、2 项跳过，包含真实 Electron 托盘测试与真实 DSH 插件网关、通知应答测试。
- DFY 插件的 54 个导入接口检查通过；工具调度、并发与取消、审批、会话回放、原生消息桥接和图片准入的运行时检查通过。
- 组合包完成独立安装迁移、逐组件启停、整体启停以及配置和数据保留验证。现有版本范围接受 `0.2.0-rc.1`，不需要为本次升级单独发布插件。
- 使用隔离的 DSH Home 和桌面配置启动、重启开发版，没有读取真实会话或更改日常插件设置。组合包详情、图像生成、Codex 连接、壁纸和外观设置页正常。
- 深浅色切换与标题栏同步正常。保存深色后重启，页面从 `theme=dark` 启动；从 DOM 就绪到 Harness 加载完成的主题记录均为深色。
- 深色壁纸可见，开关与滑块正常显示，壁纸下拉菜单右边缘与触发按钮对齐。
- 内置浏览器可以加载中文路径的本地 HTML；新建空白标签页、重新展开空白标签页时，地址栏均自动获得焦点。
- 在隔离 Electron 进程中使用 Chromium 虚拟音频设备验证：Harness 页面的麦克风策略允许访问，`getUserMedia({ audio: true })` 获得虚拟音轨并能正常停止；未访问真实麦克风。这不替代 macOS 实机授权或完整语音转写验证。

已生成 Windows x64 本地安装包，核对包内桌面端与 Harness 版本均为 `0.2.0-rc.1`，并使用打包后的可执行文件和启动器通过 `dsh --version` 验证；同时生成 SHA-256 校验文件。发布工作流生成 Windows x64、macOS Intel / Apple Silicon 安装包及校验文件，使用仓库内的版本更新说明创建预发布版。官方桌面端特有的引导、窗口和菜单实现不随 Web profile 自动接入本项目。
